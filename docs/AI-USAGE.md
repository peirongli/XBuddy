# AI 使用与验证记录

## 使用的 AI 工具

| 工具 | 用途 |
|---|---|
| WorkBuddy（GLM 智能体，AI Coding） | 全程结对开发：架构设计、代码生成、Bug 定位、测试编写、文档撰写 |
| DeepSeek API（deepseek-chat） | **产品运行时**的 Agent 能力：任务规划、步骤摘要、上下文压缩、报告综合、合规改写、记忆沉淀 |

## AI 参与的环节

1. **需求拆解**：解析题目要求 → 提炼出"Harness 机制 × 投研体验"双主线 → 生成任务清单（6 项）。
2. **架构决策**：提出并对比了数据源/LLM/部署三组 A/B 方案（扶摇 key 三选一、DeepSeek vs 纯规则引擎、本地 vs 发布），按约束收敛。
3. **代码实现**：服务端（Express + SSE + Harness 状态机）、客户端 SPA、工具注册表、DEMO 数据层均由 AI 生成，人工决策关键设计（审批阈值语义、降级链顺序、证据链结构）。
4. **接口对接**：AI 读取扶摇 llms-full.txt 提取 9 组端点精确规格（含文档中"prices/historical 实际路径"等易错点）。
5. **测试与调试**：AI 编写 24 例单元测试，并实际运行、根据失败结果修复缺陷（见下）。

## AI 产出中的错误与人工/迭代修正记录

以下错误均由**运行验证发现**（非静默通过），AI 定位根因并修复：

1. **`llmAvailable` 导入错误**：context.js 从 llm.js 导入了不存在的导出 → 服务启动即崩。修正为从 config.js 导入。
2. **goals 接口返回空**：`startRun` 为 async 但路由未 await，返回了 Promise → `run_id` 丢失。重构为"同步建 run、异步执行"。
3. **`budget is not defined`**：重构后残留旧变量引用 → 规划后 run 崩溃。改为 `run.budget`。
4. **emit 签名不匹配（核心 bug）**：`withDemoFallback` 内 `ctx.emit('mode_switch', ...)` 与执行器 `emit(run, type, payload)` 签名冲突，`run` 位置被传入字符串 → `search_ticker` 步骤 TypeError 失败且降级披露事件丢失。改为绑定 run 的箭头函数。
5. **依赖失败仍带坏参数执行**：s1 检索失败后，s2/s3 的 `{{s1.item[0].thscode}}` 引用无法解析仍发起调用。新增**级联跳过**机制。
6. **derive_metrics 读不到证据原文**：只读了 run.evidence 的摘要字段（无 data）。改为按 evidence_id 从证据库读取。
7. **DEMO 数据口径不自洽**：快照价与 K 线末收来自独立随机序列，报告主动暴露了这一矛盾（这本身验证了披露机制）。重构 mock 使快照与 K 线共享价格序列。
8. **合规 redact 自触发**：改写文案含"目标价"字样，再次触发扫描器（单测捕获）。修正替换文案。
9. **UX 缺口**：选中线程不自动加载最近运行与报告；跨 Tab 弹窗残留。均已修复。
10. **多引用参数模板未解析（真实数据回归发现）**：接入真实扶摇 key 后的回归测试中，LLM 规划器生成 `thscodes: "{{s3.item[0].thscode}},{{s3.item[1].thscode}},..."`（逗号拼接多引用），而参数解析器只支持"整串单引用"（全串锚定正则），导致未解析模板被直传 API 报 `Unknown A-share thscode`。重构为支持内嵌/多引用逐段解析（失败段丢弃并防逗号残留；整串失败保留模板原样显式暴露）。修复过程中第一版正则 `(.+)` 贪婪匹配又把多引用误判为单引用，被新增单测捕获后收紧为 `[^{}]+`。
11. **审批/恢复机制从未实测**：此前计划审批虽实测过，但"审批等待中进程被杀 → 重启后补交审批 → 从检查点恢复"与"运行中手动停止"两条路径未跑过。回归中实测通过（详见 TESTING.md 场景七）。
12. **财务摘要跨表字段混印 undefined（终检回归发现）**：`digestOf('financials')` 对利润表/资产负债表/现金流量表三组行统一打印同一组字段，而利润表行没有 `assets_total`/`holder_equity_total`/`act_cash_flow_net`（分属另两张表），导致步骤摘要出现"总资产 undefined"，LLM 摘要器忠实复述后又被写进报告 `data_gaps`（"字段返回undefined"）——数据实际并未缺失，属于摘要层误导。修复为按表分组打印各表字段，并新增回归单测（digest 不含 undefined、利润表段不含资产负债字段）。
13. **模板规划器实体提取吞入语境词 → 研究错误标的（公网验证发现）**：公网 DEMO 站（无 LLM、走模板规划）提交"分析贵州茅台近一年基本面与估值水位"，`firstEntity` 贪婪捕获把"近一年基本面"粘进实体（q="贵州茅台近一年基本面"），DEMO 检索匹配不到预置标的时又**随机返回一只真实股票**（宁德时代），导致 Agent 静默研究了错误标的——违反"不静默生成"原则。修复两处：①实体提取剥离语境词（近一年/基本面/估值等）并拆分对比语境粘连的双标的；②DEMO 未收录标的改为按查询确定性构造演示标的（名称=查询本身），不再随机冒充。新增 3 例回归单测。

## 验证方式

- 单元/契约测试：`npm test`，24 例覆盖合规守卫、规划器路由、工具注册表、上下文摘要（含财务 digest 分组回归）、DEMO 自洽性（含未收录标的构造回归）、参数引用解析（含多引用回归）。
- 端到端 API 测试：curl 驱动完整链路（建线程 → 提交目标 → 轮询状态 → 检查产物/证据/记忆），含低阈值触发审批门的专项场景（plan_approval_threshold=5 → awaiting_approval → 批准 → completed）。
- 真实数据回归（2026-09-30 接入扶摇 key 后）：单标的基本面+估值（6/6 步全 REAL）、盘面情绪（涨停池/热股榜/龙虎榜真实调用）、双银行对比（9/9 步全 REAL，报告含两行真实财务对比）；期间发现并修复缺陷 #10。
- 崩溃恢复实测：审批等待期 kill 进程 → 重启 → 补交审批（`decideApprovalAfterRestart`）→ run 转 `recoverable` → `POST /resume` 从检查点续跑至 `completed`（9/9 步，`run_resumed` 事件可见）。
- 中途停止实测：运行中 `POST /stop` → 干净停在已完成步骤，无产物、无编造报告。
- 浏览器实测：agent-browser 驱动 Chromium 实际打开页面，截图验证首页、报告、图表、证据弹窗、可观测性、记忆库六个界面；真实数据模式下复核徽章（扶摇·真实）与真实 K 线渲染。
- 失败路径实测：无扶摇 key 运行 → 自动降级 DEMO 且 `mode_switch` 事件与报告披露均出现。

## 诚实声明

- 产品运行时的报告内容由 DeepSeek 生成，但其合规性由**代码级守卫**（规则扫描 + 机械改写兜底）保证，不依赖模型自觉。
- DEMO 模式的所有数据为构造数据，报告标题、摘要、正文、证据索引均已标注，这是设计目标而非缺陷。
